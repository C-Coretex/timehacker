# Conventions

## Layering

Dependencies point inward and are declared only via `<ProjectReference>`; solution folders mirror the intended direction: `01_Presentation` (TimeHacker.Api) → `02_Application` (Contracts, Application.Api) → `03_Domain` (Domain, Domain.Services) ← `04_Infrastructure` (Infrastructure, Migrations, Identity pairs) with `05_Helpers` underneath everything.

- `TimeHacker.Api` composes everything and registers it through extension methods: `RegisterRepositories` (Infrastructure), `RegisterIdentity`, `RegisterDomainServices`, `RegisterAppServices`.
- Domain and Domain.Services take no EF Core / ASP.NET package references; `Domain.Services` is registered as scoped services/processors, not classes called directly by controllers.
- Controllers never touch repositories or `DbContext`; they call `I*AppService` from Contracts. That interface boundary is why `Application.Api` itself has no direct `TimeHacker.Domain` project reference — it goes through Contracts.
- Repositories expose read queries as `IQueryable` and forbid ad-hoc bulk writes: `RepositoryBase.ExecuteUpdateAsync`/`ExecuteDeleteAsync` are `protected`, with the class comment stating that a service needing one should get a purpose-built repository method. `SaveChangesAsync` is the scoped-DbContext unit of work and commits every repository's pending changes.
- Analyzers are enforced mechanically: warnings-as-errors is on for the solution, so a new CA rule violation fails the build. `src/.editorconfig` downgrades the specific rules the codebase intentionally breaks — `CA1062` (argument null-checking) for `**/Controllers/**` and `TimeHacker.Migrations/**`, `CA1515` for `TimeHacker.Api/**` and the test projects, and demotes CA1707/CA1859/CA5394/CA1716/CA1812/CA1307 to `suggestion` (CA5394 matters: the scheduler uses `Random.Shared` deliberately) while turning CA2007 off entirely. Local escapes use `#pragma warning disable` with a comment naming the rule (e.g. `CA1062` in the interceptors, `EF1001` in `RlsMigrationsModelDiffer`).
- `Directory.Packages.props` centralises every version (central package management; csproj files carry `<PackageReference Include=... />` with no `Version`). EF Core / Npgsql / Identity are pinned together at 10.0.x, and the file's first `ItemGroup` exists solely to override vulnerable transitive dependencies (`Microsoft.OpenApi`, `NuGet.Protocol`, `NuGet.Packaging`).

## Patterns

- **DTO triple.** Every Contracts DTO is a `record` with a static `Expression<Func<TEntity, TDto>> Selector`, a compiled `CreateFunc`/`Create(entity)` for in-memory use, and `GetEntity(entity = null)` writing the writable fields back. Reads project through `Selector`; writes go through `GetEntity`. Fields the DTO must not write (e.g. `CategoryScheduleDto.ScheduleEntity`, owned by `ScheduleEntityAppService`) are deliberately absent from `GetEntity` and say so in a comment.
- **Repository reads take pipeline steps.** `GetAll(params IEnumerable<QueryPipelineStep<TModel>>)` = `Func<IQueryable<T>, IQueryable<T>>` includes, declared once per aggregate in `Application.Api/QueryPipelineSteps/QueryPipeline*.cs` (e.g. `QueryPipelineCategorySchedules.IncludeCategory`). Includes are not written inline at call sites. Caution: an `Include` is discarded once the query ends in a projection, hence `ScheduleEntityService.Project` re-selects `CategorySchedule.Category` explicitly.
- **Query shape: stream, don't buffer, where the client streams.** Controllers returning `IAsyncEnumerable<T>` are ordinary `Ok(SomeAsyncEnumerable)`, and `TaskService.GetTasksForDays`/`RefreshTasksForDays` are `async IAsyncEnumerable` with `[EnumeratorCancellation]` that accumulate tracked entities and `SaveChangesAsync` after the last `yield`.
- **Error handling.** Domain throws `NotFoundException`/`NotProvidedException`/`DataIsNotCorrectException`/`UserAlreadyPresentException`/`UserDoesNotExistException` (`TimeHacker.Domain/BusinessLogicExceptions`) or `UnauthorizedAccessException`. `LogExceptionFilter` maps them to `ProblemDetails` (404/400/409/401) with an `ExceptionType` extension, adds `traceId`, exposes the message+stack trace only in Development, and counts the event in telemetry; anything unrecognized is logged at Error (source-message generator) and becomes a 500. Non-MVC endpoints (the minimal-API Identity surface) bypass that filter and fall back to `UseExceptionHandler`'s status selector. The UI maps these shapes back through `utils/getApiErrorMessage.ts`.
- **Two JSON converter registrations, on purpose.** `AddJsonOptions` covers MVC input binding and the `InputRepeatingEntityTypeConverter` (polymorphic `RepeatingEntity` by `entityType`); `ConfigureHttpJsonOptions` is separately required because `TypedResults` serialise through the HTTP JSON options. A new shared converter must be added to `AddSharedJsonConverters` so both paths get it.
- **Typed, RPC-ish controllers.** `[Authorize]` + `[ApiController]` + string route with a leading slash (`[Route("/api/categories")]`), `{id:guid}` constraints, `TypedResults.Ok/Created/NoContent` return types, and `[ProducesResponseType]` per status. Route constraints are load-bearing: `/api/categories/schedules` (recurrence) coexists with `/api/categories/{categoryId:guid}/schedules` only because of `:guid`. Secondary services are pulled in per action with `[FromServices]` rather than constructor injection when only one action needs them.
- **Api models ≠ DTOs.** `Api/Models/Input/*Model` expose `CreateDto(...)` (often with extra arguments such as a parent id) and `Api/Models/Return/*Model` expose `Create(dto)`. Neither is generated; both are hand-written per endpoint pair.
- **Timestamps and concurrency.** `TimestampInterceptor` stamps created/updated timestamps on `SaveChangesAsync`; `ExecuteUpdate`/`ExecuteDelete` bypass it, so `RepositoryBase.UpdateProperty` appends `UpdatedTimestamp` via a cached reflection-built selector (skipped for non-`IUpdatable` models). Optimistic concurrency uses the Postgres `xmin` system column; a `DbUpdateConcurrencyException` becomes 409.
- **Time and colour encoding.** `DateTimeUtcConverter` (Infrastructure) normalises stored DateTimes to UTC; `DateTimeUtcJsonConverter` and `ColorJsonConverter` shape the wire format, and colours are a signed ARGB int32 end to end (`utils/colorArgb.ts` in the UI). Days and windows use `DateOnly`/`TimeOnly` rather than timestamps — a `CategorySchedule` "lands on its date" exactly as a `FixedTask` lands on its `StartTimestamp`.
- **Recurrence encoding.** `RepeatingEntityType` 1–5 (Day/Week/Month/Year/Once) is mirrored as a TS discriminated union in `api/types.ts`; `OnceRepeatingEntity` carries explicit dates. Expansion has no closed form — `ScheduleEntityReturn.GetNextEntityDatesIn` iterates the pattern with a 10,000-iteration cap, and a `null` from `GetNextTaskDate` means the series is over.
- **Telemetry is first-class.** `TimeHacker.Domain/Observability/TimeHackerTelemetry` holds meter/counter/histogram names consumed by both `Program.cs` and the processors; spans like `timeline.generate` are started next to the code they measure. `Program.cs` exports OTLP when an endpoint is configured and falls back to the console exporter for tests and bare `dotnet run`.
- **UI conventions.** Imports use bare aliases mapped in `vite.config.ts` (`api/...`, `hooks/...`, `pages/...`, `components/...`) — no `src/` prefix, and no `@` alias. Server state goes through `@tanstack/react-query` (QueryClient created at module scope) via per-entity hooks (`useCategories`, `useCategorySchedules`, `useEntityCrud`), while `api/*.ts` are small hand-written axios modules with a `const API_BASE_URL` and JSDoc'd functions, not generated clients. `Router basename="/app"` must stay in sync with `APP_BASE` in `api/api.ts` and the SPA-fallback plugin; the build emits two entries (`index.html`, `app/index.html`). 401s are intercepted globally and redirect to `/app/login?expired=true`, except for `/api/users/me` and the login/register endpoints.
- **Documentation drift to distrust.** `src/TimeHacker.UI/README.md` documents `GET /api/User/GetCurrent` (the real route is `GET /api/users/me`) and `hooks/useQuery.ts`/`useMutation.ts` (they do not exist; the hooks directory holds per-entity hooks plus `useEntityCrud.ts`), and refers to `components/UnifiedTaskFormModal.tsx` where the repository has a `UnifiedTaskFormModal/` directory. Believe the code.
- **Known backlog visible in comments.** The dynamic-task algorithm is explicitly a placeholder: hard cap of 10 tasks per day, a `takeCount` heuristic over time-slot length, recursive scoring, and several `TODO`s saying a real external solver should replace it and that some scheduling-quality metrics may be dropped.

## Tests

Five test projects, all xunit.v3 with AwesomeAssertions (not FluentAssertions) and AutoBogus for data.

- **Unit** — `src/TimeHacker.Domain.Services.Tests` (scheduler and schedule-entity logic) and `src/TimeHacker.Application.Api.Tests` (app services). Moq + `MockQueryable.Moq` for `IQueryable` repositories, `Microsoft.Extensions.TimeProvider.Testing` for `TimeProvider`, and `Xunit.Combinatorial` for parameterised cases. These run without Docker.
- **DB integration** — `src/TimeHacker.Integration.Db.Tests`: a Testcontainers `postgres:latest` fixture (`Fixtures/DbContainerFixture.cs`) mounts `Resources/timehacker_infrastructure_init.sql` into `docker-entrypoint-initdb.d` (a copy of `src/postgres/…` that must be kept in step, copied to output by the csproj), runs `TimeHackerMigrationsDbContext.ApplyMigrations` with the admin connection, and exposes both the admin and `application_user` connection strings plus a Respawn resetter. Files split into `OverallDatabaseTests/` (schema-level: user scoping, cascade deletes, optimistic concurrency, timestamp population, constraints, value converters, repeating-entity JSON) and `ServiceFlowTests/` (app services against the real database), over `DbIntegrationTestBase` plus `Fixtures/GraphSeeder.cs`, `SeedDataBuilder.cs` and `UserFixture.cs`.
- **API integration** — `src/TimeHacker.Integration.Api.Tests`: `Fixtures/ApiTestFixture.cs` starts two containers (main + identity), applies both migrations, and builds `WebApplicationFactory<Program>` via `TimeHackerApiFactory`, which injects connection strings as `ConnectionStrings__*` environment variables in its constructor because `Program.cs` reads configuration before `builder.Build()`, where `ConfigureAppConfiguration` would be too late. `Fixtures/Api/TimeHackerApi.cs` is a composite Refit client grouped per controller (`api.Categories.CreateCategory(...)`); `Fixtures/AssemblyFixtures.cs` registers the fixture assembly-wide and **disables parallelisation** because Respawn clears the database after each test.
- Conventions a change should follow: assert multi-user behaviour through `CreateAdminDbContext()`/the admin connection (RLS hides other users from the app user), choose the app-connection client when the point *is* isolation, reset via the fixture rather than leaving rows behind, and expect the health endpoint to return 503 through `CreateBrokenDbApiClient()` when a database is unreachable.
- **No UI tests, no test runner in `src/TimeHacker.UI/package.json`** — frontend checks are `npm run lint` (eslint) and `tsc -b` as the first step of `npm run build`.
- CI is only `.github/workflows/codeql.yml`: weekly, skipped unless `origin/main` has a commit in the last 7 days, analysing `csharp` and `javascript-typescript` in build-mode `none`. There is no workflow that runs the tests.

The modules these rules apply to are listed in [MODULES.md](MODULES.md).
